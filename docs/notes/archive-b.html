Type b: the music decompressor (bzip-like block sorter)

TOUR3.XM, the 2.89 MB module that is the whole soundtrack (26 orders, 20 channels, 21 samples, 152 s), is stored as 2.15 MB with a bzip-style pipeline: Burrows-Wheeler transform, move-to-front, run-length symbols and a canonical Huffman code (function 0x130136). The stream is a plain MSB-first bit stream; the bit reader refills three bytes at a time with bswap and a mask.

Each block starts with its length, the BWT primary index and the Huffman table: 5-bit codes give lengths 2..18, with extra codes for "repeat previous length 2-7 times" and "2-7 / 8-23 / 24-55 zero lengths". Decoding uses an 8-bit lookup table of tree nodes (a longer code falls back to a bit-by-bit tree walk with add edx,edx / sbb ebp,ebp). While decoding, the program fills the BWT's T vector (rank of each byte among equal bytes) so the inverse transform is one pass, walking backwards through the block. The code patches its own immediates (the 0x3e7 in the listing) with buffer addresses at run time. The sample data inside the XM is ordinary delta-coded 8/16-bit PCM: no hidden structure beyond the standard XM format.

# file:  u32 total, u32 blocksize, then blocks until u32 n == 0; MSB-first bit stream
# block: u32 n, u32 idx, code-length table (5-bit codes, repeats/zero runs), n Huffman symbols

for each symbol: c = mtf.pop(s); mtf.insert(0, c); L[i] = c; T[i] = cnt[c]; cnt[c] += 1
C[c] = sum(cnt[:c])
