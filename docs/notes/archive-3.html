Type 3 (and 1): adaptive-Huffman LZ

RYMDLEGO.XM (74 016 bytes, a second tracker module the script never plays) uses type 3, an LZ coder whose fields are not stored in fixed bit widths but coded by five adaptive Huffman models of 256 symbols each: match length, distance high byte, distance low byte, literal-run length and literal bytes (0x12a019). Every model is a FGK-style tree kept in sorted arrays (weights, children, parents): each decoded symbol increments its leaf, swaps it with the highest slot of smaller weight (the sibling property) and repeats up to the root; when the root weight reaches a per-model limit (0xe00, 0x1c00, 0x200, 0x800, 0x480) all weights are halved and the tree is rebuilt (0x12a1ee). Bits are read MSB first with add al,al and the carry flag.

The stream alternates "literal run, match, literal run ..."; after every match a single raw bit tells whether a literal run follows. Type 1 (M_30_210.BIN, 256 bytes) is just the byte RLE at 0x129ea8, and type 4 (order-N PPM with an arithmetic coder reading straight from the FILE, 0x12ffa6) is in the executable but unused by this archive.
