The triangle fillers: self-modifying templates

There is no generic rasteriser in TOUR. For every combination of material mode and target depth the build contains a template: a setup routine that computes the screen-space plane gradients of the texture coordinates from the three vertices, walks the edges in 16.16 fixed point and writes the gradients into the immediate operands of the scanline loop (self-modifying code, which is why the PMODE/W image has to be loaded writable). The inner loops are tiny. Texture coordinates are kept as an 8 bit integer part in cl/ch (u, v: 256x256 textures that wrap by themselves) and a fraction in the high half of esi/ebx; the carry of the 32 bit add feeds the byte-wide adc, so one pair of instructions per axis steps the texture address. No perspective correction.

// scene3d-raster.js: same sampling positions, plane-equation attributes in floating point
function fillENV32(dst, ro, xs, xe, y) {            // dst = tex32[(v<<8)|u]
  const u0 = P[0] + P[2]*y, du = P[1], v0 = P[3] + P[5]*y, dv = P[4];
  for (let x = xs; x < xe; x++)
    dst[ro + x] = tex[((((v0 + dv*x + 65536) | 0) & 255) << 8) | (((u0 + du*x + 65536) | 0) & 255)];
}
xs = Math.ceil(xl - (1 - 0xfff0/65536)); xe = Math.ceil(xr - (1 - 0xffe0/65536));   // (x+0xfff0)>>16, (x+0xffe0)>>16
Modes
3 textured (tex32), 4 env 8 bit (palette & 0xfcfcfc), 2 lit (64K ramp [light:texel]), 0x84 two textures (64K table), 0x24 alpha glass
Fidelity
silhouettes: 99.7 % of the covered pixels identical; interior mean error 0.3-1 per channel (the original's fixed-point rounding, fitted colour tables)
Speed
1.6 - 4.5 ms per frame in node 22 for the five scenes (tentacle: 2741 triangles)
