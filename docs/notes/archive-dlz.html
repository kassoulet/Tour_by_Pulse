TOUR.98: the archive and the dlz decoder

All demo data lives in one file, TOUR.98: a chain of 116 records [u32 usize][u32 csize][u32 namelen][u32 dataofs][u32 nameofs][u32 dataend][u8 type][name\0][data]. The loader (around 0x10774d, strings "No archive file!!!" / "File not found") reads every header once, then freads the payload of the requested name and dispatches on the type byte at 0x107b94: 0 stored, 1 byte RLE, 2/t dlz, 3 adaptive-Huffman LZ, 4 order-N PPM + arithmetic coding (code present, no record uses it), b block-sorting coder, j/p raw JPEG/PNG. A type 2 record whose packed size is not smaller than the unpacked size is simply copied.

The workhorse is "dlz" (0x129ed8, 55 + 3 records): a PKLITE-style LZ. Flag bits come from a 16-bit word consumed LSB first. The trick is that dec dl does not touch the carry flag, so the bit that shr bp,1 shifted out is still in CF when the counter test is done; the offset high byte is even assembled with rcl bh,1, pushing stream bits straight into a register. Offsets are negative 16-bit values (high byte starts at 0xff), lengths use a small unary prefix code, and a 0xff offset byte with a zero flag ends the stream.

129fd7  shr bp,1            ; next flag bit -> CF (bp = 16-bit bit word)
129fda  dec dl              ; DEC leaves CF alone: bit counter 16..0
129fdc  jne 0x129fe5
129fde  lodsw               ; counter hit 0: refill 16 bits

129fea  ...                 ; (next bit, then) lodsb: low byte of the offset
