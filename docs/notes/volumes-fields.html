volume3D, copyvolume, morphvolume, mulvolume... — scalar fields as named blocks of floats

The cube sequence of Tour (script order 13-16) is driven by a tiny "volume" language that lives in the source file blob.c. volume3D NAME [file] allocates a 16×16×16 field of 32-bit floats (16 KB) and registers it under a name: the engine keeps a table of 32 pointers at 0x2041f0, every later effect looks its volumes up by name with a linear string search (and puts()+exit()s with "Volume not found" if it fails). The optional file is the raw 16 KB dump (v8.dat, vbox.dat). The run function of volume3D is a bare ret; the other effects just apply a kernel on the 4096 floats every frame: copyvolume, addvolume, subvolume, mulvolume, fadevolume (v·f) and morphvolume (a·t + b·(1−t)). The factor of fade/morph is a script expression of Frame, evaluated every frame by the engine's expression compiler (0x14a408 compiles, 0x14a570 evaluates).

The kernels are unrolled by four with the x87 FPU: load, multiply, store, 16 bytes per iteration. All values are computed with the 64-bit mantissa of the FPU stack and rounded to float only when stored, which is why the JS port (double arithmetic, Float32Array store) reproduces every one of the 4096 floats bit for bit. One detail found by testing: the evaluated factor is a float (rounded) before the kernel uses it.

; morphvolume kernel 0x15225c   eax=dst edx=A ebx=B ecx=4096 (count/4), st0=t, st1=1-t

FX.register('morphvolume', {
  init(params, ev, ctx) { const p = words(params); return { d: find(p[0]), a: find(p[1]), b: find(p[2]), f: expr(p[3]) }; },
  run(st, ev) { const t = f32(st.f(f32(ev.local))), u = 1 - t;
    for (let i = 0; i < 4096; i++) st.d[i] = st.a[i] * t + st.b[i] * u; },   // Float32Array store = fstp dword
});
