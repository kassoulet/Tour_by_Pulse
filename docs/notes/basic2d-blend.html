blend — saturated additive compositing with MMX

blend {A B} {OUT} {mode} combines two buffers byte by byte. The script only uses mode 1: SCREEN = SCREEN + EFXLAYER (the glow layer over the low-res plasma) and TEMP + PPRO. The adds are saturating (an overflowing channel sticks at 255 instead of wrapping), which is exactly what the MMX instruction paddusb does on 8 bytes at once. The original also contains a pure integer fallback for CPUs without MMX (a global flag at 0x1d1b88 selects it), built from the classic SWAR trick of adding the low 7 bits of every byte and patching up the carry bit.

The mode number is the whole parameter (atoi), and the buffer is treated as a flat byte array of w*h*bpp/8 bytes, so alpha takes part in the add. Other modes found in the dispatcher at 0x10f76b: 2 colour-key (source pixel 0 is transparent), 3 saturated subtract, 11 double add, 22 colour key = first pixel of the second input, 33 which ends up writing zeros (psubusb mm0,mm0) - all ported and checked, none used by the script.

; mode 1, MMX path (0x1e7a8)  esi=A edi=OUT ebx=B  ecx=byte count
1e7a8  neg ecx
1e7aa  sub esi, ecx               ; point past the end, count up from -n
1e7ac  sub ebx, ecx
1e7ae  sub edi, ecx
1e7b0  movq mm0, [esi+ecx]
1e7b4  paddusb mm0, [ebx+ecx]     ; 8 byte-wise saturating adds
1e7b8  movq [edi+ecx], mm0
1e7bc  add ecx, 8
1e7c2  jne 0x1e7b0
1e7c4  emms

; the non-MMX fallback (0x1e73b, self-modifying: the pointers are patched into the loads) halves each byte, adds and re-doubles with a
; carry mask:   a & 0xfefefefe + b & 0xfefefefe ... 1e772 and edx,0x1010100 ; carry bits ; sub ebp,edx ; or esi,ebp

const r = ((x & 0x7f7f7f7f) + (y & 0x7f7f7f7f)) ^ ((x ^ y) & 0x80808080);  // 4 byte sums without inter-byte carry
const c = ((x & y) | ((x | y) & ~r)) & 0x80808080;                          // bytes that overflowed
o[i] = r | ((c >>> 7) * 255);                                          // saturate them to 0xff
