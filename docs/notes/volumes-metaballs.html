metaballs — eight soft spheres summed into a 16×16×16 field

metaballs VOLUME file.mbs reads a text file of eight lines, one ball each: X Y Z R C, five expressions of Frame (sin(Frame*0.006*3.4+5.4) ... radius 1.2, strength 0.90 or -0.9 to carve holes). Every frame each ball is added to the field (nothing clears it: the script runs copyvolume first). A ball contributes only inside its radius R, with the smooth quartic f(d²) = (A d² + B) d² + C, A = C/R⁴, B = −2C/R²: value C at the centre, value and slope zero at the edge, so balls blend into each other like metal drops. The 16 grid points per axis sit at (i−8)·0.25.

The renderer (0x114ee8) is written for speed: the squared distances along each axis are computed once (3×16 floats on the stack), the loops are clipped to the bounding box of the sphere by scanning those tables from both ends, and the inner loop is a pure polynomial evaluation with one test. The ball table holds 16 records of 0x3c bytes (type, R², R, A, B, C, X, Y, Z, bounding box); only type 1 is ever created (a type 2 renderer exists at 0x115314 but nothing calls 0x114e4c with it).

; inner loop of the ball renderer, 0x1151d7 (st0 = d2 as float; esi = &volume cell)
1151d7  fld dword [esp+ebx]        ; dx2[x]
1151da  fadd dword [esp+0xec]      ; + (dy2+dz2)
1151e1  fst dword [esp+0xf0]       ; d2 stored as float
1151e8  fcomp dword [edx+4]        ; d2 < R2 ?
1151ee  jae 0x115208               ; no: skip
1151f0  fld dword [esp+0xf0]
1151f7  fld st(0)
1151f9  fmul dword [edx+0xc]       ; d2*A
1151fc  fadd dword [edx+0x10]      ; + B
1151ff  fmulp st(1)                ; * d2
115201  fadd dword [edx+0x14]      ; + C
115204  fadd dword [ecx]           ; + volume[cell]
115206  fstp dword [ecx]

for (let x = x0; x <= x1; x++, p++) {
  const d2 = f32(dx2[x] + t);
  if (d2 < R2) vol[p] += (d2 * A + B) * d2 + C;
}
script
metaballs nazwa5 {} {} {OurVolume test1.mbs} (also a.mbs, b.mbs, c.mbs, test2.mbs exist)
quirk
A = C/(R·R·R²) is computed in the FPU with a 64-bit mantissa and then rounded to float; the port emulates that single step with BigInt to stay bit-exact
verified
test1.mbs: 4096/4096 floats identical at 7 frames. a.mbs differs by ≤1 ulp at some frames because the original evaluator rounds 0.90*clip(Frame*0.0002,0,1) to float
