# Volume effects + marching cubes (Tour) - reverse notes

Module: `docs/js/fx/volumes.js`. Test: `tools/test-volumes.mjs` (reference generated by `cd re/dt_volumes && $PY gen.py`, ~1 s; dumps in `re/dt_volumes/ref/`).
Disassembly dumps: `re/dt_volumes/*.asm`; `tritab.py` extracts the 256-case triangle table from the image.
Source file name in the binary: `blob.c` (same lineage as 73MS, but see the differences below).

## Volumes
* Volume = 16x16x16 float32 = 0x4000 bytes, index `x + 16*y + 256*z`. Record (malloc 0x28): +0x20 data pointer, +0x24 slot index; the registry is the table of 32 pointers at `0x2041f0`
  (lookup = linear strcmp of the name stored in the record, error text "Volume not found" -> puts + exit; ">32" -> "Too many volumes!!!"). JS: `ctx.volumes` Map (key = lower-case name).
* `volume3D NAME [file]` (init 0x115688, run = ret): file = raw 0x4000 bytes (v1..v8.dat, vbox.dat).
* clearvolume (memclr 0x400 x 16 bytes), copyvolume DST SRC (state: [0]=src? both pointers), add/sub/mul `DST A B` (kernels 0x1521f2/0x152227/0x1521bd, 4 floats per iteration, x87),
  fadevolume `DST SRC expr` (0x15218c), morphvolume `DST A B t` = A*t + B*(1-t) (0x15225c).
  Run functions with an expression: `Frame` = `[0x1b28f8]` - start time stored on the first run ("started" flag in the state), passed to the evaluator as a float.
  The value returned by the evaluator is rounded to float before use (verified: fade and morph are bit-exact only with f32(t)).
* plasma1volume `DST a b`: table 16^3 floats of sqrt((x-7.5)^2+(y-7.5)^2+(z-7.5)^2) at 0x2001f0 (init); run: v = a + b*sin(dist + Frame*0.02) for one octant, mirrored (4 stores per sine), planes z<8 copied to 15-z.
  a, b are evaluated each frame and stored as floats.
* metaballs `DST file`: 8 lines `X Y Z R C` (expressions, 5 whitespace separated words; an '@' line = end). Run: each ball (evaluated C,R,Z,Y,X, all stored as float) sets a 0x3c-byte record in a 16-record table
  (0x114e4c: +0 type 1, +4 R2=R*R (float), +8 R, +0xc A=C/(R*R*R2) (x87 64-bit mantissa product, then float), +0x10 B=-2C/R2, +0x14 C, +0x18..0x20 X,Y,Z, +0x24..0x38 bbox init 0/15) and
  `0x1155cc` renders all records: type 1 -> 0x114ee8 (quartic falloff added to the volume, never cleared by the effect), type 2 -> 0x115314 (never created). Grid coordinate of index i = (i-8)*0.25 on every axis.
  Exact port: `addBall`. The `A` division needs x87 emulation (BigInt in ballA) to be bit-exact for every radius.
* Original uses 80-bit intermediates: where results are stored as float, JS double arithmetic matched bit for bit in all tests except that single A computation.

## Differences to 73MS (pls73ms volumes.js)
* marchingcubes params are `SCENE OBJECT VOLUME FLAG` (4, `%s %s %s %d`), no threshold expression: threshold constant 0.65f (`0x3f266666` stored to `[0x1f6330]` by every run).
* the polygoniser core is at 0x151ab8 (`eax`=face buffer, `edx`=vertex buffer, `ebx`=volume data), vertex fill at 0x106e54, mesh allocation `0x114cac`; the cell step is `(max-min)*0.06666667f` (float constant 0x1add93, not 1/15).
* metaball renderer is table-driven (0x3c records, 2 types), no per-call arrays in the effect state.
* Triangle table (0x1b340c + case*64, int32 vertex offsets /0x60 -> slot codes, -1 terminated) and 1/sqrt table (0x1b7414) are identical to the 73MS ones (checked: all 256 cases equal, table equal to the generating formula).
* volumesprites (0x1168ac, not in the script) is not ported.

## Marching cubes - what the original writes into the object (for the 3D agent)
`0x114cac(eax=object, edx=0xfa0 max faces, ebx=flag)` builds the mesh state (malloc 0x30): +0..+8 step (max-min)*0.0666667 per axis, +0xc..+0x14 min per axis (object-space bbox `obj+0xbc..+0xd0`, floats),
+0x18 obj, +0x1c face buffer (0xfa0*0x3c bytes), +0x20 vertex buffer 0x120000 bytes, +0x24 = 0x3000, +0x28 = 0xfa0. Then it patches the object:

| object field | value |
|---|---|
| obj+4 | 2 if flag != 0 (Gouraud) else 1 (flat) |
| obj+8 | vertex buffer |
| obj+0x10 | vertex count = 0x3000 (all 3x4096 slots are always "present"; only referenced ones are meaningful) |
| obj+0x18 | face buffer; face[0] is a copy of the object's first original face (material/flags), the whole buffer is filled by replicating it (0x3c bytes) |
| obj+0x1c | face count, written after each run (= (end-start)/0x3c); also added to a global counter at 0x1d1b6c |

Vertex slot = 0x60 bytes: +0 x, +4 y, +8 z (object space), +0xc nx, +0x10 ny, +0x14 nz (unit-ish normal = interpolated -gradient, points out of the blob); the rest is the 3D pipeline's scratch (+0x34... transformed data).
Slots: array 0 (x-edges) = slots 0..4095, array 1 (y edges) 4096.., array 2 (z-edges) 8192..; an edge between samples s and s-1 / s-16 / s-256 lives at slot s-1 / 4096+s-16 / 8192+s-256.
Face record = 0x3c bytes: +0x10 vertex count (3), +0x14 +0x18 +0x1c face normal = (B-A)x(C-A) (not normalised), +0x24..+0x2c / +0x30..+0x38 pointers to (vertex+0x34) / vertex of A,B,C; other fields = copy of face[0].
Positions: `pos_k = min_k + step_k * (coord) ` with the coordinate along the edge interpolated (`sp*c + (min - t*sp)`, t = (v1-thr)/(v1-v0)); the other two coordinates are static per slot (`min + i*step`).
Triangles are emitted in the original order (z, y, x scan, table order); winding as in the table.
Samples: x,y,z map to object space x,y,z directly (no axis swap); the cube covers exactly the object's bbox (sample 0 at min, sample 15 at max).

## JS contract (docs/js/fx/volumes.js, effect `marchingcubes`)
`init`: finds the scene event: `ctx.engine.events.find(e => e.name.toLowerCase() === SCENE)`; its `.state` (S) may provide
* `S.getObjectBBox(objName) -> [xmin,ymin,zmin,xmax,ymax,zmax]` (object-space bbox = obj+0xbc..0xd0; fallback: parse the EXP through `./3d/formats.js` `parseEXP` as in 73MS, else error),
* `S.setObjectMesh(objName, mesh)` with `mesh = {pos: Float32Array(3n), idx: Uint32Array(3m), nrm: Float32Array(3n), faceNormals: Float32Array(3m), smooth: bool}` called every frame
  (the arrays are views into reused buffers: copy if you keep them; vertices are compacted and shared, normals are per vertex = Gouraud, `smooth=false` => use faceNormals/flat).
If `setObjectMesh` is missing the mesh is stored in `S.lastMesh` and in the effect state `.lastMesh`. The renderer must replace the object's mesh keeping its material (original keeps face[0]'s).
Face limit: the original buffer holds 4000 faces and does not check; the script's volumes stay below (test: <=3360).

## Verification (tools/test-volumes.mjs vs original in Unicorn)
plasma, copy/mul/add/sub/fade/morph: 4096/4096 floats bit-identical at 7 frames. metaballs test1/c: bit-identical; a.mbs: bit-identical at 6 of 7 frames, 1 ulp (<=2e-8 abs) at F=300 because the original
evaluator rounds `0.90*clip(Frame*0.0002,0,1)` to float32 somewhere (0.0539999977 vs the double evaluator's 0.0540000014) - a core.js `compileExpr` matter (note for the engine owner: function results / literals are float32).
marching cubes (5 volumes, 224..3360 triangles): triangle count, all vertex slot indices, every position, normal and face normal bit-identical (max error 0).
